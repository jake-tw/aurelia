# Review Skill

檢查 skill 文件是否符合項目規範，驗證文件結構、frontmatter 配置、內容質量。

## 輸入

- **skill-name**（必須）：要檢查的技能名稱（kebab-case），或完整路徑
  - 範例：`create-skill` 或 `docs/skills/create-skill/SKILL.md`

## 步驟

### 1. 定位技能文件

- 如果輸入是完整路徑，直接使用
- 如果輸入是技能名稱，查找 `docs/skills/<skill-name>/SKILL.md`
- 如果文件不存在，報錯並列出可用技能

### 2. 基礎結構檢查

**必須存在：**
- [ ] `docs/skills/<skill-name>/` 目錄
- [ ] `SKILL.md` 文件

**可選但建議：**
- [ ] `agents/` 目錄（如果使用 sub-agent）
- [ ] 參考文檔（如 `templates.md`、`guide.md`）

### 3. Frontmatter 檢查

**必要欄位：**
- [ ] `name: <skill-name>`（kebab-case）
- [ ] `description: <一句話描述>`（< 100 字）

**配置欄位：**
- [ ] `disable-model-invocation`（如存在，檢查值是否為 `true`）
- [ ] `user-invocable`（如存在，檢查值是否為 `true` 或 `false`）

**驗證規則：**
- frontmatter 的 `name` 必須 = 文件夾名
- description 應包含：功能 + 觸發時機
- 不應有無效欄位

### 4. 內容結構檢查

**標準章節：**
- [ ] `# 標題`（H1，與 name 對應）
- [ ] 一句話說明（H1 下方）
- [ ] `## 輸入`
- [ ] `## 步驟`
- [ ] `## 輸出`

**可選章節：**
- [ ] `## 參考`（如有外部依賴）
- [ ] `## 範例`

### 5. 設計原則檢查

**可執行性：**
- [ ] 第一段能用一句話說清楚功能
- [ ] 步驟具體、可執行（避免模糊詞如"適當"、"必要時"）

**最小化：**
- [ ] SKILL.md < 200 行
- [ ] 步驟數合理：
  - 原子技能：3-7 個主步驟
  - 工作流技能：< 50 行，主要是調用其他技能

**自包含性：**
- [ ] 外部引用 < 3 個
- [ ] 引用的文件都存在

### 6. 生成報告

依據檢查結果生成報告，包含：
- 通過項目概覽（結構、frontmatter、必要章節）
- 問題列表（按嚴重程度分類：阻斷/警告/建議）
- 具體修正建議

報告格式見 `## 輸出` 章節。

### 7. 自動修正（可選）

在報告輸出後，如發現可自動修正的問題，詢問用戶是否執行：
- frontmatter 的 `name` 與文件夾名不一致
- 缺少標準章節模板
- description 格式問題

## 輸出

### 檢查報告格式

**如果全部通過：**
```
✅ Skill 檢查通過

技能：<skill-name>
描述：<description>
類型：[原子技能 / 工作流技能]
行數：XX 行

結構：✓
Frontmatter：✓
內容：✓
外部引用：X 個
```

**如果有問題：**
```
⚠️ Skill 檢查發現問題

技能：<skill-name>

❌ 阻斷問題（必須修正）：
  - frontmatter name (xxx) ≠ 文件夾名 (yyy)
  - 缺少必要章節：## 輸入

⚠️ 警告（建議修正）：
  - SKILL.md 超過 200 行 (當前 250 行)
  - 外部引用過多：5 個 (建議 < 3)
  - 步驟過多：10 個 (原子技能建議 3-7)

💡 建議：
  - 考慮拆分為多個原子技能 + 工作流技能
  - 將詳細說明移到參考文檔
```

## 檢查規則參考

### Frontmatter 規範
- **必要欄位：**
  - `name: <skill-name>`（kebab-case，必須與文件夾名相同）
  - `description: <一句話描述>`（< 100 字，包含功能 + 觸發時機）
- **配置欄位（可選）：**
  - `disable-model-invocation: true`（禁止自動調用）
  - `user-invocable: false`（隱藏，不出現在 / 選單）

### 結構規範
- **必要章節：** `## 輸入`、`## 步驟`、`## 輸出`
- **可選章節：** `## 參考`、`## 範例`
- **文件大小：** SKILL.md < 200 行
- **外部引用：** < 3 個（確保自包含性）

### 步驟數規範
- **原子技能：** 3-7 個主步驟（具體實現任務）
- **工作流技能：** < 50 行（主要調用其他技能）

### 設計原則
- **可執行性：** 第一段能用一句話說清楚功能，步驟具體明確
- **最小化：** 只做一件事，沒有"以防萬一"的內容
- **自包含：** 不看其他文檔能理解 80%
